# STM32 Security Lab v1.0.2

## Summary

Version 1.0.2 supersedes v1.0.1 as the public Open Source release candidate for
the hardware-validated STM32F429 secure-boot and dual-slot secure-update
reference.

The firmware, signed-image format, update-package format, Ed25519/SHA-512 trust
model, rollback policy, slot layout, flash layout, and public-key format are
unchanged from v1.0.1. The patch clarifies release documentation and publishes
explicit higher-version update artifacts for positive A/B update tests.

## What Changed Since v1.0.1

- Clarified that default EXP066 Slot A/Slot B packages use image version `2`.
- Documented that positive updates from a confirmed version-2 image require a
  strictly higher package version.
- Added release-artifact guidance for Slot B version `3` and Slot A version `4`
  packages matching the hardware-validation campaign.

## Hardware Validation Status

The v1.0.2 release points to the same validated code baseline as v1.0.1:

- confirmed Slot A boot with SHA-512 and Ed25519 executed before jump;
- A-to-B authenticated update to Slot B version `3`;
- Slot B trial boot and application confirmation;
- B-to-A authenticated update to Slot A version `4`;
- Slot A trial boot and application confirmation;
- rollback rejection for same and lower image versions;
- fail-closed rejection of corrupted manifest, target, signature, and payload
  cases;
- abort and reset during `WRITING` preserving the confirmed fallback slot;
- UART CRC, sequence, partial-frame, and random-byte negative cases;
- byte-for-byte flash readback for both positive update targets;
- unchanged RDP0 Option Bytes during the campaign.

## Release Artifacts

The release bundle contains:

- EXP045 bootloader ELF/BIN/HEX;
- EXP066 Slot A and Slot B ELF/BIN/HEX;
- default Slot A and Slot B version-2 update packages for provisioning and
  offline verification;
- Slot B version-3 update package for positive A-to-B update testing;
- Slot A version-4 update package for positive B-to-A update testing;
- package build, inspect, and verify JSON reports;
- `firmware_public_key.h`;
- `SHA256SUMS`;
- release notes.

Private signing seeds and private keys are not release artifacts and must never
be uploaded.

## Security Boundaries

This release does not approve:

- RDP1 or RDP2 provisioning;
- Option Byte, WRP, OTP, or irreversible hardware configuration changes;
- production signing-key custody, rotation, or revocation;
- hardware-backed monotonic rollback counters;
- physical recovery input;
- certified fault-injection, glitch, or side-channel resistance;
- production remote-update authorization beyond signed firmware packages and
  rollback policy.

Physical power-removal timing and visual LED observations should be repeated
for each board and power setup before any irreversible protection planning.
