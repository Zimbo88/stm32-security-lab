# Property and model testing

`tests/test_security_properties.py` uses Hypothesis with bounded examples and
fixed settings for reproducible local runs. It covers:

- frame encode/decode round trips;
- malformed frame fail-closed behaviour;
- strict INFO/STATUS lengths;
- oversize frame rejection;
- arbitrary package inspection;
- one-byte mutation rejection of a deterministic test-signed package;
- deterministic fingerprints and total slot-vector mapping.

The C fuzz driver's `policy` mode is a small reference model, not a second
production implementation. It derives the expected decision from independently
decoded metadata and checks status/decision against `boot_slot_selection`.
Valid, invalid, ambiguous, empty, trial and fallback records are generated by
mutation of both metadata copies.

Hypothesis uses no network or hardware. A failing example includes the
framework's reproduction seed; the C driver records its LCG seed in `FUZZ_OK`
output and campaign JSON.

`tools/mutation_smoke.py` is a deliberately small prototype. It makes two
temporary source mutations in the Python UART parser (the maximum-payload
boundary and magic comparison) and checks that the bounded property kills
both. The temporary tree is deleted after the run; no mutated source is
written to the repository.
